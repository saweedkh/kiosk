# راهنمای کامل ربات بله و مدیریت کاربران/گروه‌ها

این سند نحوهٔ راه‌اندازی و استفاده از **مدیریت کاربران و گروه‌ها** در پنل ادمین و **ربات پیام‌رسان بله** را توضیح می‌دهد.

---

## ۱. خلاصه معماری

| بخش | نقش |
|-----|-----|
| پنل ادمین (`/admin`) | سوپریوزر کاربران/گروه‌ها را می‌سازد؛ هر کاربر فقط منوهای مجاز خودش را می‌بیند |
| اپ `accounts` | پروفایل کاربر، شناسه بله، کاتالوگ دسترسی‌ها، گروه‌های پیش‌فرض |
| اپ `bale_bot` | long polling به API بله، منوی وابسته به دسترسی، اجرای عملیات روی همان دیتابیس کیوسک |
| سرویس Docker `bale_bot` | پروسهٔ جدا از gunicorn که `manage.py bale_poll` را اجرا می‌کند |

ربات **جایگزین پنل نیست**؛ همان منطق بک‌اند را از طریق چت بله در دسترس می‌گذارد.

```
کاربر در بله  →  long polling (bale_poll)  →  بررسی chat_id و دسترسی‌ها  →  سرویس‌های Django
سوپریوزر در پنل  →  تعریف کاربر/گروه + ثبت bale_chat_id
```

---

## ۲. پیش‌نیازها

1. ساخت بازو در بله با [@BotFather](https://ble.ir/botfather) و دریافت توکن.
2. داشتن یک کاربر **سوپریوزر** در Django (`is_superuser=True`).
3. تنظیم متغیرهای محیطی در `.env` (نمونه در `.env.example`):

```env
BALE_BOT_TOKEN=123456789:xxxxxxxx
BALE_API_BASE=https://tapi.bale.ai
BALE_POLL_TIMEOUT=30
BALE_BOT_ENABLED=True
```

4. اجرای مایگریشن و گروه‌های پیش‌فرض:

```bash
cd kiosk_backend
python manage.py migrate
python manage.py setup_permission_groups
```

---

## ۳. گروه‌ها و دسترسی‌های پیش‌فرض

دستور `setup_permission_groups` این گروه‌ها را می‌سازد/به‌روز می‌کند:

### مشاهده‌گر
- مشاهده گزارشات، محصولات، دسته‌بندی‌ها، سفارش‌ها

### اپراتور (نقش پیشنهادی شما)
- همهٔ دسترسی‌های مشاهده‌گر
- افزودن محصول
- ویرایش محصول
- تغییر موجودی
- تغییر وضعیت سفارش
- **بدون** حذف محصول / حذف دسته‌بندی / تنظیمات / مدیریت کاربران

### مدیر
- تقریباً همهٔ عملیات پنل به‌جز مدیریت کاربران (مخصوص سوپریوزر)

### سوپریوزر
- همهٔ دسترسی‌ها + تب «کاربران» در پنل

اگر کاربر staff بدون گروه باشد، هنگام setup به‌صورت خودکار در گروه **مدیر** قرار می‌گیرد تا از پنل قفل نشود.

---

## ۴. مدیریت کاربران در پنل (فقط سوپریوزر)

1. با حساب سوپریوزر وارد `/admin` شوید.
2. تب **کاربران** را باز کنید.
3. در بخش **گروه‌ها** می‌توانید گروه جدید بسازید یا دسترسی‌های گروه را ویرایش کنید.
4. در بخش **کاربران**:
   - کاربر جدید بسازید (نام کاربری، رمز، فعال بودن، staff)
   - یک یا چند **گروه** به او بدهید (مثلاً «اپراتور»)
   - **شناسه چت بله (`chat_id`)** را وارد کنید
   - سوییچ **دسترسی ربات بله** را روشن کنید

### چطور chat_id را پیدا کنیم؟

1. کاربر موردنظر در بله به ربات شما پیام `/start` بدهد.
2. اگر هنوز ثبت نشده باشد، ربات پیام می‌دهد و **شناسه چت** را نشان می‌دهد.
3. همان عدد را در پنل، فیلد «شناسه چت بله» وارد کنید و سوییچ دسترسی بله را روشن کنید.
4. دوباره `/start` بزند؛ منوی متناسب با گروه‌اش را می‌بیند.

---

## ۵. فعال‌سازی ربات از پنل (توکن + روشن/خاموش)

1. با سوپریوزر وارد `/admin` شوید و تب **کاربران** را باز کنید.
2. کارت **تنظیمات ربات بله** را ببینید:
   - توکن BotFather را وارد کنید
   - سوییچ **فعال‌سازی ربات بله** را روشن کنید
   - ذخیره کنید
3. وضعیت «در حال اجرا» یعنی هم فعال است و هم توکن دارد.
4. سرویس `bale_bot` بدون ری‌استارت، همین تنظیمات را از دیتابیس می‌خواند.
5. توکن در API به‌صورت کامل برنمی‌گردد (فقط masked). برای عوض کردن، توکن جدید را وارد کنید.

API:

- `GET /api/kiosk/bale/settings/`
- `PATCH /api/kiosk/bale/settings/` با `{ "is_enabled": true, "bot_token": "..." }`

اگر فیلد توکن را خالی بگذارید، توکن قبلی حفظ می‌شود. برای پاک کردن از دکمه «پاک کردن توکن» استفاده کنید.

`BALE_BOT_TOKEN` در `.env` هنوز به‌عنوان fallback کار می‌کند؛ مقدار ذخیره‌شده در پنل اولویت دارد.

---

## ۶. منوهای ربات بر اساس دسترسی

بعد از `/start`:

| دکمه منو | دسترسی لازم |
|----------|-------------|
| گزارشات | `view_reports` |
| محصولات | `view_products` |
| موجودی | `change_stock` |
| افزودن محصول | `add_products` |
| ویرایش محصول | `change_products` |
| حذف محصول | `delete_products` (در اپراتور نیست) |
| سفارش‌ها | `view_orders` |

### گزارشات
- گزارش امروز
- فروش ۷ روز
- موجودی انبار
- موجودی کم / ناموجود

### موجودی
- تنظیم موجودی به عدد مشخص
- افزایش / کاهش
- دستور سریع: `/موجودی <شناسه_محصول> <عدد>`

### محصولات
- لیست / جستجو
- افزودن چندمرحله‌ای (نام → قیمت → موجودی → دسته → **تصویر اختیاری**)
- ویرایش فیلدها (نام، قیمت، موجودی، توضیحات، **تصویر**، فعال/غیرفعال)
- حذف فقط اگر دسترسی `delete_products` باشد

تصویر از چت بله دانلود و روی فیلد `image` محصول ذخیره می‌شود؛ همان تصویر در پنل ادمین و کیوسک دیده می‌شود. برای رد کردن مرحله تصویر بنویسید: `رد`

برای انصراف از هر گفتگوی چندمرحله‌ای: `انصراف`

## ۷. اجرای ربات (Polling)

### با Docker Compose

سرویس `bale_bot` در این فایل‌ها تعریف شده:

- `docker-compose.yml`
- `docker-compose.production.yml`
- `docker-compose.production.host-network.yml`

```bash
docker compose up -d bale_bot
docker logs -f kiosk_bale_bot
```

اگر `BALE_BOT_TOKEN` خالی باشد، پروسه با خطا خارج می‌شود و در لاگ مشخص است.

### بدون Docker

```bash
cd kiosk_backend
python manage.py bale_poll
```

این دستور را **جدا از gunicorn** نگه دارید (یک پروسهٔ دائمی).

## ۸. APIهای مدیریت حساب (سوپریوزر + JWT)

پایه: `/api/kiosk/accounts/`

| متد | مسیر | توضیح |
|-----|------|--------|
| GET | `/permissions/` | کاتالوگ دسترسی‌ها |
| GET/POST | `/groups/` | لیست / ایجاد گروه |
| GET/PATCH/DELETE | `/groups/<id>/` | جزئیات گروه |
| GET/POST | `/users/` | لیست / ایجاد کاربر |
| GET/PATCH/DELETE | `/users/<id>/` | جزئیات کاربر + bale_chat_id |

نمونه بدنه ایجاد کاربر:

```json
{
  "username": "operator1",
  "password": "Secret123!",
  "first_name": "علی",
  "is_staff": true,
  "is_active": true,
  "group_ids": [2],
  "bale_chat_id": "123456789",
  "bale_enabled": true
}
```

پاسخ لاگین ادمین حالا شامل `is_superuser`، `groups` و `permissions` است؛ فرانت با همین لیست تب‌ها را فیلتر می‌کند.

## ۹. سناریوی پیشنهادی برای نقش اپراتور

1. سوپریوزر گروه **اپراتور** را تأیید می‌کند (از قبل ساخته شده).
2. کاربر `operator1` را می‌سازد و گروه اپراتور را می‌دهد.
3. `bale_chat_id` او را ثبت و دسترسی بله را فعال می‌کند.
4. اپراتور در بله `/start` می‌زند و این‌ها را می‌بیند:
   - گزارشات
   - محصولات / موجودی
   - افزودن و ویرایش محصول
5. دکمه/مسیر حذف برای او وجود ندارد؛ اگر دستی تلاش کند، پیام «دسترسی ندارید» می‌گیرد.
6. همان کاربر در پنل وب هم فقط تب‌های مجاز (مثلاً محصولات و گزارشات) را می‌بیند.

---

## ۱۰. عیب‌یابی

| مشکل | بررسی |
|------|--------|
| ربات جواب نمی‌دهد | لاگ `kiosk_bale_bot`، صحت `BALE_BOT_TOKEN`، دسترسی اینترنت سرور به `tapi.bale.ai` |
| «دسترسی ندارید» | `bale_enabled`، تطابق `bale_chat_id`، `is_active` کاربر |
| منوی ناقص | گروه کاربر و permissionهای گروه |
| پنل تب ندارد | کاربر staff است ولی گروهی ندارد → `setup_permission_groups` را دوباره اجرا کنید |
| خطای دیتابیس بین backend و bot | هر دو باید به همان Postgres (`kiosk_db` / volume `postgres_data`) وصل باشند |

## ۱۲. محدودیت‌های نسخه فعلی

- دریافت آپدیت‌ها با **long polling** است (بدون نیاز به IP ثابت / webhook).
- آپلود تصویر محصول از بله پشتیبانی می‌شود (افزودن/ویرایش → ارسال عکس).
- مدیریت کاربران فقط برای **سوپریوزر** است.
- ارسال خودکار زمان‌بندی‌شدهٔ گزارش هنوز پیاده نشده؛ از منوی ربات یا دستورات دستی استفاده کنید.
