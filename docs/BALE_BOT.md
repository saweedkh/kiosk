## ۱. خلاصه معماری

| بخش | نقش |
|-----|-----|
| پنل ادمین (`/admin`) | سوپریوزر کاربران/گروه‌ها را می‌سازد؛ هر کاربر فقط تب‌های مجاز خودش را می‌بیند |
| اپ `accounts` | پروفایل کاربر، `bale_chat_id`، کاتالوگ دسترسی‌ها، گروه‌های پیش‌فرض |
| اپ `bale_bot` | long polling به API بله، منوی وابسته به دسترسی، اجرای عملیات روی همان DB کیوسک |
| سرویس Docker `bale_bot` | پروسهٔ جدا از gunicorn که `manage.py bale_poll` را اجرا می‌کند |

ربات **جایگزین کامل پنل نیست**؛ همان سرویس‌های Django (`OrderService`، `StockService`، `ReportService`، …) را از چت بله صدا می‌زند.

```
کاربر در بله  →  bale_poll (long polling)  →  بررسی chat_id + دسترسی  →  سرویس‌های Django
سوپریوزر      →  پنل: کاربر/گروه + bale_chat_id + تب «ربات بله» برای توکن
```

## ۲. پیش‌نیازها

1. ساخت بازو در بله با [@BotFather](https://ble.ir/botfather) و دریافت توکن.
2. یک کاربر **سوپریوزر** در Django (`is_superuser=True`).
3. متغیرهای محیطی در `.env` (نمونه در `.env.example`):

```env
BALE_BOT_TOKEN=123456789:xxxxxxxx
BALE_API_BASE=https://tapi.bale.ai
BALE_POLL_TIMEOUT=30
BALE_BOT_ENABLED=True
```

4. مایگریشن و گروه‌های پیش‌فرض:

```bash
cd kiosk_backend
python manage.py migrate
python manage.py setup_permission_groups
```

## ۳. گروه‌ها و دسترسی‌های پیش‌فرض

دستور `setup_permission_groups` این گروه‌ها را می‌سازد/به‌روز می‌کند:

### مشاهده‌گر
- مشاهده گزارشات، محصولات، دسته‌بندی‌ها، سفارش‌ها

### اپراتور (نقش پیشنهادی روزمره)
- همهٔ دسترسی‌های مشاهده‌گر
- افزودن / ویرایش محصول
- تغییر موجودی
- تغییر وضعیت سفارش (`change_orders`)
- **بدون:** حذف محصول، حذف دسته، تنظیمات سایت، مدیریت کاربران، مدیریت ربات

### مدیر
- تقریباً همهٔ عملیات پنل به‌جز مدیریت کاربران (مخصوص سوپریوزر)

### سوپریوزر
- همهٔ دسترسی‌ها + تب «کاربران» در پنل

اگر کاربر staff بدون گروه باشد، هنگام setup به‌صورت خودکار در گروه **مدیر** قرار می‌گیرد.

### نگاشت دسترسی → منوی ربات

| دسترسی | قابلیت در ربات |
|--------|----------------|
| `view_reports` | داشبورد، گزارشات |
| `view_orders` | لیست/جستجوی سفارش، صف‌های اقدام |
| `change_orders` | تغییر وضعیت سفارش و پرداخت |
| `view_products` | لیست/جستجوی محصول |
| `add_products` | افزودن محصول |
| `change_products` | ویرایش محصول |
| `delete_products` | حذف محصول |
| `change_stock` | تنظیم/افزایش/کاهش موجودی، گزارش موجودی کم |

## ۴. مدیریت کاربران در پنل (فقط سوپریوزر)

1. با سوپریوزر وارد `/admin` شوید.
2. تب **کاربران** (`manage_users`).
3. **گروه‌ها:** ساخت/ویرایش گروه و permissionها.
4. **کاربران:**
   - نام کاربری، رمز، staff، فعال بودن
   - یک یا چند گروه (مثلاً «اپراتور»)
   - **شناسه چت بله (`bale_chat_id`)**
   - سوییچ **دسترسی ربات بله (`bale_enabled`)**

### پیدا کردن `chat_id`

1. کاربر در بله به ربات `/start` بزند.
2. اگر ثبت نشده باشد، ربات **شناسه چت** را نشان می‌دهد.
3. همان عدد را در پنل وارد کنید و `bale_enabled` را روشن کنید.
4. دوباره `/start` → منوی متناسب با گروه.

## ۵. فعال‌سازی ربات از پنل

تب **ربات بله** (`manage_bale`) — نه تب کاربران:

1. توکن BotFather
2. سوییچ **فعال‌سازی ربات بله**
3. (اختیاری) آدرس API پایه — پیش‌فرض `https://tapi.bale.ai`
4. ذخیره

کارت وضعیت، سلامت polling و زمان آخرین آپدیت را نشان می‌دهد.

**API:**

- `GET /api/kiosk/bale/settings/`
- `PATCH /api/kiosk/bale/settings/` — `{ "is_enabled": true, "bot_token": "..." }`

توکن در پاسخ masked است. فیلد خالی = حفظ توکن قبلی.

**اولویت توکن:** مقدار DB (پنل) > `BALE_BOT_TOKEN` در `.env`.

**نکته ENV:** اگر `BALE_BOT_ENABLED=False` باشد، `bale_poll` اصلاً polling را شروع نمی‌کند (خروج با کد ۰). سوییچ پنل فقط وقتی اثر دارد که ENV هم روشن باشد.

## ۷. سفارش‌ها در ربات

**دسترسی:** مشاهده `view_orders` — تغییر `change_orders`

**سرویس backend:** `OrderService.update_order_status` و `OrderService.update_payment_status` — همان پنل ادمین.

### منوی سفارش‌ها

| دکمه | توضیح |
|------|--------|
| ⚠️ نیازمند اقدام | `payment_status=failed` **یا** `status` ∉ `{completed, cancelled}` |
| ❌ پرداخت ناموفق | فقط `payment_status=failed` |
| 📋 سفارش‌های امروز | همه سفارش‌های روز کاری |
| 🔍 جستجوی سفارش | با شماره سفارش |
| 🔄 تغییر وضعیت با لیست | `change_orders` — ورود از لیست/جستجو |

### نمایش وضعیت‌ها

**برچسب‌های فارسی** (در `menus.py`):

| `order.status` | برچسب |
|----------------|--------|
| `pending` | در انتظار |
| `processing` | در حال پردازش |
| `paid` | پرداخت‌شده |
| `completed` | تکمیل‌شده |
| `cancelled` | لغو‌شده |

| `payment_status` | برچسب |
|------------------|--------|
| `pending` | در انتظار |
| `processing` | در حال پردازش |
| `paid` | پرداخت‌شده |
| `failed` | ناموفق |
| `cancelled` | لغو‌شده |
| `success` | موفق (legacy) |

- **کارت جزئیات:** هر دو فیلد «وضعیت» و «پرداخت» + مبلغ، نوع سفارش، خطا (در صورت وجود).
- **لیست:** `شماره · وضعیت سفارش · آیکون+وضعیت پرداخت` (مثلاً `✅پرداخت‌شده`، `❌ناموفق`).

### تغییر وضعیت

دو منوی جدا: **🔄 وضعیت سفارش** و **💳 وضعیت پرداخت** — هر ۵ مقدار مجاز.

**میانبرهای سریع** (روی جزئیات، فقط در صورت مرتبط بودن):
- pending → «➡️ پردازش»
- paid و نه completed → «✅ تکمیل»
- failed → «💳 علامت پرداخت‌شده»

### تأیید (confirm) قبل از اعمال

| عمل | تأیید؟ |
|-----|--------|
| وضعیت سفارش → `completed` | ✅ |
| وضعیت سفارش → `cancelled` | ✅ |
| وضعیت سفارش → `paid` | ✅ (اگر پرداخت هنوز paid نباشد → مسیر پرداخت + کسر موجودی) |
| وضعیت پرداخت → `paid` | ✅ |
| وضعیت پرداخت → `cancelled` | ✅ |
| سایر تغییرات | مستقیم |

### موجودی (Stock) — رفتار یکسان با پنل

| عمل در ربات | موجودی |
|-------------|--------|
| پرداخت → `paid` (اولین بار) | **کسر** + چاپ فیش |
| سفارش → `cancelled` (بعد از paid) | **برگشت**؛ اگر payment بود paid → payment هم `cancelled` |
| پرداخت `paid` → `failed`/`cancelled`/… | **برگشت**؛ اگر status بود paid → status هم `cancelled` |
| لغo سفارش بدون پرداخت | بدون تغییر موجودی |
| تأیید/لغo همزمان | `select_for_update` — برگشت **یک‌بار** (idempotent) |

جزئیات کامل: [`ORDER_STATUS_AND_PAYMENT.md`](./ORDER_STATUS_AND_PAYMENT.md)

### ⚠️ لغo روی دستگاه POS

لغo از ربات (یا پنل) **فقط در دیتابیس** است — تراکنش روی POS لغo نمی‌شود.

## ۸. گزارشات

**دسترسی:** `view_reports`

### منوی گزارشات

| گزارش | callback | توضیح |
|--------|----------|--------|
| 📅 روز (امروز) | `report:daily` | فروش روز کاری جاری |

| 🕐 ساعتی (امروز) | `report:hourly:0` | صفحه‌بندی ساعتی |
| 🕐 ساعتی با تاریخ | `report:pick_hourly` | |
| 🗓 بازه از–تا | `report:pick_range` | دو تاریخ |
| 🗓 بازه‌های آماده | `menu:report_ranges` | امروز، دیروز، ۷ روز، ۳۰ روز |
| 📈 کامل ۷ روز | `report:sales7` | |

**تاریخ ورودی:** فرمت `1404/05/28` یا میلادی `2025-08-19`.

## ۹. محصولات و موجودی

### محصولات (`view_products` + …)

- لیست صفحه‌بندی‌شده، جستجو، جزئیات
- **افزودن** (`add_products`): نام → قیمت → موجودی → دسته → تصویر (اختیاری؛ `رد` = بدون تصویر)
- **ویرایش** (`change_products`): نام، قیمت، موجودی، توضیحات، تصویر، فعال/غیرفعال
- **حذف** (`delete_products`): با تأیید — در گروه اپراتور نیست

تصویر از چت بله دانلود و روی `Product.image` ذخیره می‌شود.

### موجودی (`change_stock`)

- 🎯 تنظیم دقیق / ➕ افزایش / ➖ کاهش
- انتخاب از لیست محصول
- دستور: `/موجودی <شناسه_محصول> <عدد>`

**دسته‌بندی:** فقط هنگام افزودن محصول (انتخاب از لیست) — CRUD دسته در ربات **نیست**.

## ۱۰. اجرای ربات (Polling)

### Docker Compose

فایل‌ها: `docker-compose.yml`، `docker-compose.production.yml`، `docker-compose.production.host-network.yml`

```bash
docker compose up -d bale_bot
docker logs -f kiosk_bale_bot
```

بعد از تغییر کد backend:

```bash
docker restart kiosk_backend kiosk_bale_bot
```

### بدون Docker

```bash
cd kiosk_backend
python manage.py bale_poll
```

یک پروسهٔ **جدا** از gunicorn — دائمی.

## ۱۱. APIهای مدیریت حساب

پایه: `/api/kiosk/accounts/` (سوپریوزر + JWT)

| متد | مسیر | توضیح |
|-----|------|--------|
| GET | `/permissions/` | کاتالوگ دسترسی‌ها |
| GET/POST | `/groups/` | لیست / ایجاد گروه |
| GET/PATCH/DELETE | `/groups/<id>/` | جزئیات گروه |
| GET/POST | `/users/` | لیست / ایجاد کاربر |
| GET/PATCH/DELETE | `/users/<id>/` | جزئیات + `bale_chat_id` |

نمونه ایجاد کاربر:

```json
{
  "username": "operator1",
  "password": "Secret123!",
  "first_name": "علی",
  "is_staff": true,
  "is_active": true,
  "group_ids": [2],
  "bale_chat_id": "123456789",
  "bale_enabled": true
}
```

## ۱۲. سناریوی پیشنهادی برای نقش اپراتور

1. سوپریوزر گروه **اپراتور** را تأیید می‌کند.
2. کاربر `operator1` + گروه اپراتور + `bale_chat_id` + `bale_enabled=true`.
3. اپراتور `/start` می‌زند:
   - داشبورد امروز (فروش، نیازمند اقدام، …)
   - سفارش‌های معطل → جزئیات → «علامت پرداخت‌شده» یا «تکمیل»
   - موجودی بحرانی → تنظیم موجودی
   - گزارش روز / ساعتی
4. **نمی‌بیند / نمی‌تواند:** حذف محصول، کوپن، تنظیمات سایت، مدیریت کاربر، تنظیمات ربات، چاپ مجدد فیش.
5. همان کاربر در پنل وب فقط تب‌های مجاز گروهش را می‌بیند.
